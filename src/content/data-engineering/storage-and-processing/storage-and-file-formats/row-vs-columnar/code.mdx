The stage's $8$ sales as Python and PySpark. The first blocks compute the two orders and the pages
a query touches; the last one writes real files and shows what a Parquet reader asks for.

## The table

```python title="sales.py" step=table check=spark
import os

import pyarrow.parquet as pq
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.getOrCreate()
columns = ["id", "day", "city", "total"]
rows = [
    (1, "Mon", "LIS", 30), (2, "Mon", "OSL", 12),
    (3, "Mon", "REC", 45), (4, "Tue", "LIS", 8),
    (5, "Tue", "REC", 20), (6, "Wed", "OSL", 17),
    (7, "Wed", "LIS", 26), (8, "Wed", "REC", 11),
]
N, C, PER_PAGE = len(rows), len(columns), 4
```

## Two orders

`slot` is the formula from the explanation: row $i$, column $j$ goes to $iC + j$ in a row layout
and to $jN + i$ in a column layout. Cutting the sequence every $4$ values gives the pages.

```python title="layouts.py" step="row-layout column-layout" focus="row-layout=1-2,9 column-layout=1-2,10" check=spark
def slot(layout: str, i: int, j: int) -> int:
    return i * C + j if layout == "row" else j * N + i

def pages(layout: str) -> list[list]:
    cells = [(i, j) for i in range(N) for j in range(C)]
    values = [rows[i][j] for i, j in sorted(cells, key=lambda c: slot(layout, *c))]
    return [values[k:k + PER_PAGE] for k in range(0, N * C, PER_PAGE)]

print(pages("row")[:2])
print(pages("column")[:3])
```

```output
[[1, 'Mon', 'LIS', 30], [2, 'Mon', 'OSL', 12]]
[[1, 2, 3, 4], [5, 6, 7, 8], ['Mon', 'Mon', 'Mon', 'Tue']]
```

## Pages a query touches

A query needs some cells; the pages it reads are the pages of those cells. The sum needs column
$3$ of every row, the lookup every column of row $5$ (id $6$).

```python title="pages.py" step="row-scan lookup" focus="row-scan=3-4,7,10-11 lookup=3-4,8,10-11" check=spark
Cell = tuple[int, int]

def pages_read(layout: str, cells: list[Cell]) -> set[int]:
    return {slot(layout, i, j) // PER_PAGE for i, j in cells}

queries = {
    "SUM(total)": [(i, 3) for i in range(N)],
    "id = 6": [(5, j) for j in range(C)],
}
for name, cells in queries.items():
    print(name, [len(pages_read(l, cells)) for l in ("row", "column")])
```

```output
SUM(total) [8, 2]
id = 6 [1, 4]
```

## A real column file

Parquet stores each column as one contiguous range of the file (a column chunk). Spark's plan asks
only for `total` (`ReadSchema`), and the reader fetches that range. A CSV file has no such ranges:
reading one column means reading every byte. On $8$ rows the file is mostly metadata, so the
sizes show the mechanism, not the ratio a large table gets.

```python title="files.py" step=column-scan colors="total=blue" check=spark
df = spark.createDataFrame(rows, "id int, day string, city string, total int")
df.coalesce(1).write.csv("sales_csv")
df.coalesce(1).write.parquet("sales_pq")
spark.read.parquet("sales_pq").select(F.sum("total")).explain("formatted")

csv = [f for f in os.listdir("sales_csv") if f.endswith(".csv")][0]
print("csv bytes:", os.path.getsize(f"sales_csv/{csv}"))
part = [f for f in os.listdir("sales_pq") if f.endswith(".parquet")][0]
chunks = pq.ParquetFile(f"sales_pq/{part}").metadata.row_group(0)
for j, name in enumerate(columns):
    print(name, "chunk bytes:", chunks.column(j).total_compressed_size)
```

```output excerpt
(1) Scan parquet
Output [1]: [total#7]
Batched: true
ReadSchema: struct<total:int>
csv bytes: 103
id chunk bytes: 62
day chunk bytes: 77
city chunk bytes: 77
total chunk bytes: 63
```

Each chunk carries a header and encoding data, so here one chunk is $63$ bytes against $103$ for
the whole CSV. With millions of rows that fixed cost is negligible, and the sum reads the `total`
chunk while the CSV reader still reads every byte of every column.
