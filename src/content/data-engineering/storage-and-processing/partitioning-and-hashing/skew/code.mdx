The stage's orders in PySpark, bucketed with Spark's hash. The keys are integers, so the buckets
are the stage's.

## Loads and the ratio

Rows per bucket for $40$ customers with $250$ orders each, and the largest load over the mean.

```python title="loads.py" step="loads ratio" focus="loads=1-28 ratio=29" colors="L=blue mean=yellow" check=spark
from pyspark.sql import Column, DataFrame, SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.getOrCreate()
HOT = 9999


def orders(keys: int, each: int, hot: int = 0) -> DataFrame:
    """`keys` customers with `each` orders, plus `hot` orders of HOT."""
    ids = [k for k in range(1, keys + 1) for _ in range(each)] + [HOT] * hot
    rows = list(enumerate(ids))
    return spark.createDataFrame(rows, "order_id int, customer_id int")


def loads(df: DataFrame, n: int, h: Column | None = None) -> list[int]:
    h = F.hash("customer_id") if h is None else h
    rows = df.groupBy(F.pmod(h, F.lit(n)).alias("b")).count().collect()
    counts = {r["b"]: r["count"] for r in rows}
    return [counts.get(b, 0) for b in range(n)]


def ratio(L: list[int]) -> float:
    return round(max(L) / (sum(L) / len(L)), 2)


L = loads(orders(40, 250), 8)
mean = sum(L) / len(L)
print(L, mean)
print(ratio(L))
```

```output
[1250, 1500, 750, 2000, 500, 1500, 1500, 1000] 1250.0
1.6
```

## A hot key

$3000$ orders of one customer and $10$ each for $700$ others. The hot bucket holds the $3000$ and
its share of the rest. With $16$ buckets the ratio grows.

```python title="hot_key.py" step="hot-key more-buckets" focus="hot-key=1-3 more-buckets=5-6" colors="L=blue" check=spark
hot = orders(700, 10, hot=3000)
L = loads(hot, 8)
print(L, ratio(L))

L = loads(hot, 16)
print(L, ratio(L))
```

## Salting

Salting: the hot key's rows take salts in turn, and their bucket comes from the hash of the pair
(key, salt). The ratio is $1.48$ here and $1.67$ on the stage, which hashes the pair as text.
AQE: Spark's adaptive execution splits a skewed join partition by itself; the thresholds are
lowered so that a few kilobytes count (the defaults are $256$ MB and $5$ times the median).

<CodeTabs>

```python title="salting.py" tab=Salting step=salting colors="L=blue" check=spark
S = 8
salt = F.col("order_id") % S
h = F.when(
    F.col("customer_id") == HOT, F.hash("customer_id", salt)
).otherwise(F.hash("customer_id"))
L = loads(hot, 8, h)
print(L, ratio(L))
```

```output
[960, 1285, 1215, 960, 1855, 1275, 1640, 810] 1.48
```

```python title="aqe.py" tab=AQE step=salting check=spark
conf = {
    "spark.sql.autoBroadcastJoinThreshold": -1,
    "spark.sql.shuffle.partitions": 8,
    "spark.sql.adaptive.coalescePartitions.enabled": False,
    "spark.sql.adaptive.skewJoin.skewedPartitionFactor": 2,
    "spark.sql.adaptive.skewJoin.skewedPartitionThresholdInBytes": "100B",
    "spark.sql.adaptive.advisoryPartitionSizeInBytes": "4KB",
}
for key, value in conf.items():
    spark.conf.set(key, value)

customers = spark.createDataFrame(
    [(k,) for k in [*range(1, 701), HOT]], "customer_id int"
)
note = F.sha2(F.col("order_id").cast("string"), 256)  # wider rows
wide = hot.withColumn("note", note).repartition(8)
joined = wide.join(customers, "customer_id")
joined.collect()  # AQE re-plans once the shuffle has run
joined.explain()
```
